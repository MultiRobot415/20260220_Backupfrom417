## 2025-08-07 リーダー交代時の目標位置継承バグ修正 🎯

### 1. 問題の概要

#### 発生していた問題
- リーダー交代は検出されるが、新リーダーが旧リーダーの目標位置を引き継がない
- 初期状態：1号機（リーダー）[0,1,0]、2号機（フォロワー）[0,1,1]
- リーダー交代後：2号機が新リーダーになるが目標位置が[0,1,0]に更新されない
- フォーメーション制御で新フォロワー（1号機）がZ軸-1mの位置に配置される問題
- 信頼度しきい値の継続条件により即座にリーダー交代しない問題

#### 根本原因の特定
1. **リーダー交代検出ロジックの不具合**
   - `previous_leader_idx`が毎回現在値で上書きされ、リーダー交代を検出できない
   - リーダー交代処理が重複実装されており、処理が競合

2. **フォーメーション制御のスコープ問題**
   - リーダー交代処理で`current_leader_idx`を更新
   - しかし、フォーメーション制御が古い`current_leader_idx`を参照
   - スコープの問題により更新が伝わらない

3. **信頼度しきい値の継続条件**
   - `fault_counter_threshold = 3`により0.3秒の継続が必要
   - 即座のリーダー交代を阻害

### 2. 修正内容

#### A. リーダー交代検出ロジックの修正
```python
# mocap_for_2tellos.py (75-85行目)
# グローバル変数として管理
previous_leader_idx = 0  # 前回のリーダーインデックス

# 制御ループ内（892-920行目）
if new_leader_idx != previous_leader_idx:
    print(f"🔄 リーダー交代検出: {previous_leader_idx+1}号機 → {new_leader_idx+1}号機")
    
    # 旧リーダーの目標位置を取得
    old_leader_target = controllers[previous_leader_idx].get_target_position()
    print(f"📍 旧リーダー目標位置: {old_leader_target}")
    
    # 新リーダーに目標位置を設定
    controllers[new_leader_idx].set_target_position(*old_leader_target)
    print(f"✅ 新リーダー目標位置継承完了: {old_leader_target}")
    
    # previous_leader_idxを更新（重要：検出後に更新）
    previous_leader_idx = new_leader_idx
```

#### B. フォーメーション制御のスコープ修正
```python
# mocap_for_2tellos.py (1224行目付近)
# フォーメーション制御直前で最新のリーダーインデックスを取得
current_leader_idx = droneObserver.get_leader_index()
print(f"🔄 フォーメーション制御: 最新リーダーインデックス = {current_leader_idx}")
```

#### C. フォーメーションオフセットの修正
```python
# position_control.py (500行目)
if self.drone_id == 0:  # 1号機がフォロワーの場合
    self.formation_offset = [0.0, 0.0, 1.0]  # Z軸方向に+1mオフセット
```

#### D. 信頼度しきい値の即時反応化
```python
# observer.py (71行目)
self.fault_counter_threshold = 1  # 故障と判定するカウント閾値（即座に検出）
```

## 2025-07-31 Tモード関連の改善

### 1. T/Mキー動作の仕様修正

#### 問題点
- Tキー、Mキーがトグル動作になっており、短時間に複数回押すことでモードが不安定に切り替わる
- 特にTキーを連打した際に、一瞬autoモードに入った後すぐにmanualモードに戻る現象が発生
- ユーザーの期待する動作と実装が一致していなかった

#### 修正内容
- Tキーを「manualモード→autoモードのみ」に変更（autoモード中はTキーを押しても状態維持）
  - mocap_for_2tellos.py内のTキー処理ロジックを修正
  - 状態遷移条件を明確化し、デバウンス処理も改善
  - CSV Debug Logに詳細な状態遷移情報を記録

- Mキーを「autoモード→manualモードのみ」に変更（manualモード中はMキーを押しても状態維持）
  - mocap_for_2tellos.py内のMキー処理ロジックを修正
  - 既にmanualモードの場合は状態を維持する条件を追加

#### 効果
- モード切替の安定性が向上
- ユーザーの意図しないモード切替が発生しにくくなった
- ログ記録を強化したことで、問題発生時の診断が容易になった

### 2. Tモード目標位置操作キーの修正

#### 問題点
- UIには「T-Mode Position Control: G:Forward B:Back V:Left N:Right」と表示されているが、実際にはこれらのキーが機能していなかった
- キー入力があっても目標位置が変更されない

#### 原因調査結果
- keyboard_control.pyのキー監視リスト（`keys_to_check`）にG/B/V/Nキーが含まれていなかった
- そのため、これらのキーが押されてもキー入力が検出されず、処理されなかった
- システムの座標系は「X:前後、Y:上下、Z:左右」であることも確認

#### 修正内容
- keyboard_control.pyのキー監視リスト（`keys_to_check`）にG/B/V/Nキーを追加
```python
keys_to_check = [
    'a', 'd', 'w', 's',              # 上下移動、左右回転
    'UP', 'DOWN', 'LEFT', 'RIGHT',   # 前後、左右移動
    'q', 'e',                        # 離陸、着陸
    't', 'm',                        # 自動ホバリング切替, 手動モード切替
    'g', 'b', 'v', 'n',              # Tモード目標位置操作（前/後/左/右）
    'f', 'r',                        # 故障注入/解除（Fモード）
    'z',                             # 目標位置リセット
    '1', '2', '0',                   # ドローン選択（1・2・全）
    'ESCAPE', 'SPACE'                # 緊急停止、通常停止
]
```

- mocap_for_2tellos.pyでのキー処理実装を確認
  - G/Bキー: X軸（前後方向）の目標位置変更
  - V/Nキー: Z軸（左右方向）の目標位置変更
  - システムの座標系に適合していることを確認

#### 効果
- Tモード（自動モード）中にG/B/V/Nキーを使って目標位置を操作できるようになった
- 目標位置の変更がリアルタイムに反映され、ドローンがその位置へ移動するようになった
- control_logにも目標位置変更が適切に記録されるようになった

## 2025-07-30 MOCAPデータログ記録改善

### 問題点
1. MOCAPデータがダミー値としてログに記録される問題
   - control_log.csvの`x`,`y`,`z`列に実測値でなくゼロが記録される
   - MOCAPシステム接続中でもデータが記録されない

2. manualモードでMOCAPデータが記録されない問題
   - 自動制御（Tモード）時のみMOCAPデータを取得していた
   - 手動制御時にはMOCAPデータのログ記録をスキップしていた

3. データのダミーフラグ処理が不適切
   - `is_mocap_available`フラグを利用してダミーデータ判定していた

### 修正内容
1. MOCAPデータ処理を改善
   - MOCAPデータをタプル形式(位置データ, ダミーフラグ)に変更
   - CSVロガーでダミーデータか実データかを区別して処理
   - 警告メッセージを追加して問題の早期発見を支援

2. マニュアルモード時のログ記録処理を改善
   - 制御モードに関わらずMOCAPデータを常に記録するよう修正
   - log_control_dataの呼び出しをmanualモード時にも実行

3. log_control_data呼び出しの修正
   - キーワード引数名の不一致を修正（control_anomaly→control_anomaly_count）

## 注意事項と今後の課題

2. キー入力監視の包括的実装

3. モード切替の安全性向上
   - 不意なモード切替を防ぐため、明示的な状態遷移条件を維持
   - 異常検知時は適切なフォールバック動作を実装

4. データログの継続的な改善
   - ログデータの品質を定期的に確認
