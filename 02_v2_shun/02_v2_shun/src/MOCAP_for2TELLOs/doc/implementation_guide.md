# MOCAP for 2 TELLOs フォーメーション制御システム 実装ガイド

## 1. プロジェクト概要

本プロジェクトは、モーションキャプチャシステム（MOCAP）を用いた2機のTello EDUドローンによる**リーダーフォロワー型フォーメーション制御システム**です。Phase 1では合意アルゴリズムに基づく安定した横一列編隊飛行を実現し、実機検証にて完全な成功を収めました。

### 🎯 プロジェクトの目標
- **Phase 1 (完成)**: リーダーフォロワー型フォーメーション制御
  - 横一列、1m間隔の安定編隊飛行
  - 合意アルゴリズムによる協調制御
  - リーダー操作に対するフォロワーの自動追従
- **Phase 2 (予定)**: 信頼度ベースの動的リーダー交代機能
  - 故障検知・自動リーダー切替
  - フォルトトレラント制御

### 🔧 技術仕様
- **座標系**: 右手系（X: 前後、Y: 上下、Z: 左右）
- **制御方式**: P制御 + フォーメーション制御（合意アルゴリズム）
- **フォーメーション**: 横一列、1m間隔（Z軸方向）
- **制御周期**: 100ms（10Hz）
- **制御値制限**: ±20（安全性重視の統一制限）
- **開発言語**: Python 3

### 📶 MOCAPデータの統合仕様

**フォーメーション制御におけるMOCAPデータの役割**:

#### 🎯 データ仕様
- **座標系**: 右手系 (X: 前後、Y: 上下、Z: 左右)
- **精度**: ミリメートル精度の高精度位置情報
- **ダミーフラグ**: MOCAP接続状態を示すフラグ付き
- **リアルタイム更新**: 100ms周期で連続取得

#### 🔄 フォーメーション制御での利用
1. **位置フィードバック**: 各ドローンの現在位置を高精度で取得
2. **相対位置計算**: ドローン間の距離・方向を精密計算

4. **ダミーデータの扱い**
   - MOCAPシステム未接続時または特定RigidBodyのデータ取得失敗時に「ダミー」フラグを付与
   - ダミーデータはログに警告表示され、位置値は0.0として記録
   - ダミーフラグはドローンごとに個別に管理（部分的なデータ欠損に対応）

## 4. モジュール詳細

### 4.1 custom_tello.py
- **概要**：TelloドローンのUDP通信と基本コマンド実装
- **主要クラス**：実行しよう
  - `CustomTello`：Telloドローンとの通信・制御
  - `TelloManager`：複数のTelloドローンを管理
- **主要機能**：
  - UDP通信でTelloドローンにコマンド送信
  - 基本的な飛行コマンド（離陸、着陸、移動など）
  - バッテリー・状態情報の取得
  - 複数のTelloドローンの検出と管理

### 4.2 keyboard_control.py
- **概要**：キーボード入力を検出し、ドローン制御に必要な機能を提供
- **主要機能**：
  - Pygame利用によるキー入力検出
  - 特定キーの押下状態取得
  - 複数の同時押しに対応

### 4.3 mocap_stream.py
- **概要**：OptiTrackモーションキャプチャシステムからのデータ受信・処理
- **主要機能**：
  - UDPパケットの受信と解析
  - リジッドボディの位置・姿勢情報の抽出
  - マルチスレッドによる非同期データ処理

### 4.4 position_control.py
- **概要**：P制御（比例制御）による位置制御アルゴリズム
- **主要クラス**：
  - `PositionController`：位置制御計算を行うクラス
- **主要機能**：
  - 目標位置と現在位置の差に基づいた制御値計算
  - ゲイン調整機能
  - 不感帯設定による微小振動抑制

### 4.5 tello_double_control_test.py
- **概要**：2機のTelloドローン接続・制御確認テスト用モジュール(メインとは依存無)
- **主要機能**：
  - 2機のドローン検出・接続
  - キーボードによる手動制御
  - 同時離陸・着陸制御
  - MOCAP無しでのドローン接続テスト．基本使う必要はない．不調の際の要因切り分け用

### 4.6 mocap_stream_test.py
- **概要**：MOCAPデータ受信確認テストプログラム
- **主要機能**：
  - MOCAPシステムからのデータ受信・表示
  - 指定したリジッドボディの位置・姿勢情報の監視

### 4.7 observer.py 🆕
- **概要**：ルーエンバーガーオブザーバーによる状態推定と故障検知システム
- **主要クラス**：
  - `StateObserver`：単一ドローンの状態推定・故障検知
  - `DroneObserver`：複数ドローンの統合管理
- **主要機能**：
  - 論文通りのルーエンバーガーオブザーバー実装（固定ゲインL使用）
  - 制御入力を考慮した状態推定（位置・速度）
  - 残差ベース故障検知（しきい値: 0.5）
  - 信頼度メトリクス計算（段階的減衰モデル）
  - 故障注入機能（Fキーによる手動注入）

### 4.8 leader_switching.py 🆕
- **概要**：動的リーダー交代システム
- **主要クラス**：
  - `LeaderSelector`：信頼度ベースリーダー選定
- **主要機能**：
  - 緊急交代モード（信頼度0.3以下で即座に交代）
  - 固定バックアップリーダー（常に2号機に交代）
  - 交代履歴管理とデバッグ出力
  - 交代判定の詳細ログ記録

### 4.9 fault_handler.py 🆕
- **概要**：故障注入システム
- **主要クラス**：
  - `FaultHandler`：故障パターン管理・制御値修正
- **主要機能**：
  - ピッチハードオーバー故障の実装
  - 対象ドローン指定による故障注入
  - 故障継続時間管理
  - 制御値修正とデバッグ出力

### 4.10 csv_logger.py（Phase 2拡張）
- **概要**：包括的CSVログシステム（Phase 2で大幅拡張）
- **主要機能**：
  - 制御データログ（role、trust_metric等を追加）
  - オブザーバーデータログ（残差、推定状態、信頼度）
  - デバッグイベントログ（リーダー交代、故障注入等）
  - 単一ファイル管理による一貫性確保

### 4.11 mocap_for_2tellos.py（統合システム）
- **概要**：Phase 1&2統合メインプログラム（フォーメーション制御＋オブザーバー）
- **主要機能**：
  - 2機のドローン初期化・制御
  - MOCAPシステムからの位置情報取得
  - フォーメーション制御（リーダーフォロワー型、Z軸1m間隔）
  - roleベース目標位置割り当て
  - オブザーバーによる状態推定・故障検知
  - 動的リーダー交代機能
  - 故障注入システム統合
  - 手動/autoモード切替
  - 制御フロー順序最適化（正常制御値でオブザーバー推定→故障注入→送信）

### 4.8 observer.py (Phase 2 新規モジュール)
- **概要**: 残差アルゴリズムによる状態推定・故障検知システム
- **主要クラス**:
  - `StateObserver`: 個別ドローンの状態推定・故障検知
  - `DroneObserver`: 全体管理・リーダー選出統合
- **主要機能**:
  - 残差ベースの故障検知 (fault_threshold = 0.4)
  - 信頼度計算・管理 (0.1〜1.0範囲)
  - 継続的な闾値超過による信頼度低下
  - 即座故障検知 (fault_counter_threshold = 1)

### 4.9 leader_switching.py (Phase 2 新規モジュール)
- **概要**: 信頼度ベースのリーダー選出アルゴリズム
- **主要クラス**:
  - `LeaderSelector`: 信頼度に基づくリーダー選出
- **主要機能**:
  - 信頼度しきい値判定 (emergency_threshold = 0.25)
  - 最高信頼度ドローンをリーダーに選出
  - リーダー交代イベントの検出・通知

### 4.10 csv_logger.py (Phase 2 新規モジュール)
- **概要**: 制御データ・オブザーバーデータの包括的CSVログ記録
- **主要クラス**:
  - `CSVLogger`: マルチファイルCSVログ管理
- **主要機能**:
  - control_log.csv: 制御データ・フォーメーション状態記録

- **最適化済み**: 個体差を考慮した安定性重視の設定

**2. フォーメーション制御ゲイン**
```python
# フォーメーション制御ゲイン（合意アルゴリズム）

```
- **役割**: ドローン間の相対位置制御・編隊維持

- **k2**: 安定性確保（大きく→ダンピング向上・応答性低下）

## 6. 注意事項と安全機能

- バッテリー残量の定期的な確認と警告

### モーションキャプチャなしでの動作
モーションキャプチャシステムが接続されていない場合、以下の仕様になります：

1. 警告メッセージを表示します。

3. 自動ホバリングモード（Tモード）は使用できません。切替えようとすると警告メッセージが表示されます。
4. ログは通常通り`results/`ディレクトリに記録されます。

## 8. トラブルシューティング

### ドローンが検出されない場合
- ドローンの電源と無線LAN接続を確認
- コンピュータと同一ネットワークに接続されているか確認
- コンピュータのファイアウォールが通信をブロックしていないか確認


### MOCAPシステムからデータが受信できない場合
- MOCAPシステムのIPアドレスと接続ポートを確認
- UDPパケット通信がファイアウォールでブロックされていないか確認
- リジッドボディIDが正しく設定されているか確認
- **注意**: MOCAP未接続でも手動モード（Manualモード）では動作可能です。Mキーを押して手動モードを確実に有効化してください。

### 位置制御が安定しない場合
- P制御のゲイン値を調整（不安定な場合は下げる）
- 不感帯の値を調整
- MOCAPシステムのキャリブレーションを再確認
