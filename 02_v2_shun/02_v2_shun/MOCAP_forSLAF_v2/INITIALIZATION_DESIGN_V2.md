# v2オブザーバ型SLAF 初期化設計

## 設計概要

### 新しい初期化フロー（2025年12月11日改訂）

v2オブザーバ性能検証のため、初期化を**2段階**に分けた設計を採用：

#### **フェーズ1: T押下時（制御開始）**
- **目的**: SLAF制御を開始し、ドローンを安定させる
- **初期化内容**:
  - 初期位置 = 現在のMOCAP位置
  - 初期目標位置 = 現在のMOCAP位置
  - 初期推定位置 = 現在のMOCAP位置
  - **推定誤差ゼロ**
  
#### **フェーズ2: H押下時（軌道追従開始）**
- **目的**: 指定位置から目標軌道追従を開始し、オブザーバ性能を検証
- **初期化内容**:
  - 初期目標位置 = `H_MODE_INITIAL_TARGET_POSITION`（絶対座標、MOCAP座標系）
  - 初期推定位置 = `H_MODE_INITIAL_ESTIMATION_POSITION`（絶対座標、MOCAP座標系）
    - `None` の場合：現在のMOCAP位置を使用 → 推定誤差ゼロ
    - 座標指定時：その値を使用 → 推定誤差あり
  - **推定誤差 = `p_hat_H - p_actual(H時点)`**
  - 実位置 `p_actual` はMOCAPから取得し続ける（変更しない）
  - 目標速度 = 0、目標加速度に基づいて軌道生成開始

---

## 理論的根拠

### 設計の正当性

1. **T押下時（推定誤差ゼロ）**:
   - v1と同様の初期化
   - 理論（v4_observer.tex 定理4.2）のAssumption 3.1に合致
   - ドローンを安定させてから軌道追従を開始する実用的な運用

2. **H押下時（推定誤差あり）**:
   - 「新しい初期条件での軌道追従開始」と位置づける
   - H押下時点を**新しい時刻 t=0** と見なせば、定理4.2が適用可能
   - 推定器の状態を人為的にリセットしているが、これは実験検証のための意図的な操作

### オブザーバの収束性

H押下時点を時刻 t=0 とすると：

```
推定誤差: e(0) = p_hat(0) - p(0) = p_hat_H - p_actual(H時点)
速度推定誤差: e_v(0) = v_hat(0) - v(0) = 0
```

定理4.2により、推定誤差は指数的に減衰：

```
||e(t)|| ≤ ||e(0)|| * exp(-λ_min * K_obs * t)
```

ここで、`λ_min`はシステム行列の最小固有値、`K_obs`はオブザーバゲイン。

## 重要な実装上の注意点

### H押下時の処理フロー

**H押下時の処理**：

```python
# mocap_slaf_main.py 行450-468
for follower_id in [3, 4]:
    # 1. 初期目標位置を設定（絶対座標）
    p_star_H = H_MODE_INITIAL_TARGET_POSITION.get(follower_id)
    
    # 2. 現在の実位置を取得（MOCAPから）
    p_actual_current = controller.p_actual.copy()
    
    # 3. 初期推定位置を設定（絶対座標 or None）
    p_hat_H_config = H_MODE_INITIAL_ESTIMATION_POSITION.get(follower_id)
    if p_hat_H_config is None:
        p_hat_H = p_actual_current.copy()  # 実位置を使用
    else:
        p_hat_H = np.array(p_hat_H_config)  # 指定座標を使用
    
    # 4. 推定位置のみを設定（実位置は変更しない）
    controller.set_estimated_state(p_hat_H, v_hat_H)
```

**重要**：
- `set_estimated_state()` は `p_hat` と `v_hat` **のみ**を設定
- `p_actual` は**一切変更しない**（MOCAPから取得し続ける）
- `just_initialized` フラグは**立てない**（実位置との同期は不要）

## 運用フロー

### 標準的な実験手順

1. **プログラム起動**: `python mocap_slaf_main.py`
2. **Q押下**: ドローン離陸
3. **T押下**: SLAF制御開始
   - 初期位置 = 現在位置
   - 推定誤差ゼロ
   - ドローンが安定
4. **H押下**: 軌道追従開始
   - 目標位置と推定位置を指定値に設定
   - 推定誤差を与える（オブザーバ性能検証）
   - 目標軌道生成開始
5. **J押下**: 軌道追従停止（必要に応じて）
6. **E押下**: 着陸

- 様々な初期条件で検証可能

### 3. 明確性 ✅

- 2つのフェーズが明確に区別される

### 4. 理論的整合性 ✅

## 注意事項

### 1. H押下時の状態リセット
- H押下時に推定器の状態がリセットされる
- これは実験検証のための意図的な操作であり、通常運用では推奨されない

### 2. 実位置との乖離
- H押下時、目標位置が現在のMOCAP位置と異なる場合、ドローンが大きく移動する可能性
- 安全な範囲内で設定すること

### 3. 推定誤差の大きさ
- 推定誤差が大きすぎるとドローンが不安定になる可能性
- 推奨: 0.1m～0.5m程度から開始
